# CLAUDE.md — native/ (Swift rewrite)

This loads alongside the root `CLAUDE.md` when running `claude` from `native/`. Root working agreement (Michael runs git/deploys/signing, phase-driven sessions, surgical edits, "don't guess unknown APIs") still applies. This file only adds Swift-specific stack rules. Full plan: `Tech/todo-sync/native/swift-rewrite-plan.md` in the Obsidian vault; per-phase briefs: `Tech/todo-sync/native/phase-N*.md`.

## What this is

A from-scratch native Swift/SwiftUI rewrite of todo-sync, replacing the archived Avalonia client (`src/`, `tests/`, `Todo.slnx` at the repo root — reference only, never edited). The Cloudflare Worker + D1 backend (`worker/`) and its wire protocol are shared with the archived client. The Worker changes only additively (new nullable/defaulted columns, new optional DTO fields), each as a numbered D1 migration; N8's `sort_order` was the first.

## Stack (locked)

- Swift 6, SwiftUI, one multiplatform app target (`TodoNative`) with macOS (native, not Catalyst) and iOS destinations.
- Minimums: iOS 26 / macOS 26.
- Shared logic lives in the local Swift package `TodoNativeCore` (models, store, sync, recurrence, notifications) — the app target is UI plus DI wiring only, same "no platform code in the shared layer" discipline as the Avalonia `Todo.Core` project.
- Local store: SwiftData. No Core Data, no third-party persistence. The store lives in the **App Group container** `group.com.aurlaw.todonative` so the app, the Share extension and the widgets extension open the same file.
- Sync: existing Worker + D1, existing bearer token, existing wire format (`worker/src/index.ts` / `worker/src/types.ts`). Worker changes are additive only and ship as a numbered D1 migration that Michael applies and deploys (Claude never runs `--remote` or `wrangler deploy`); deploy the migration before the Worker code, and the Worker before the client.
- Reminders: native `UNUserNotificationCenter` on both platforms.
- Zero third-party dependencies. Apple frameworks only.
- Naming: everything Swift-side uses the `TodoNative` prefix (package `TodoNativeCore`, test target `TodoNativeCoreTests`, bundle id `com.aurlaw.TodoNative` — capital T and N, as created in Xcode; the Keychain service string is separate and stays lowercase, `com.aurlaw.todonative`). Nothing in `native/` is named plain `Todo`.

## Gotchas

- **SwiftData's `@Model` macro reserves the exact property name `isDeleted`** — a stored property with that name silently resets to `false` on every `context.save()` (confirmed by an isolated repro: set `true`, save, read back `false`; no error, no warning). This is presumably `@Model`'s own soft-delete/tombstone bookkeeping colliding with a same-named user property. `TodoItem`'s soft-delete flag is named `isSoftDeleted` instead — never name a `@Model` property `isDeleted`.
- `Package.swift` accepts `.macOS(.v26)` / `.iOS(.v26)` platform requirements under `swift-tools-version: 6.3` (confirmed buildable with the installed Xcode 26.6 / Swift 6.3.3 toolchain) — no need to fall back to an older platform floor.
- `TodoStore` is `@MainActor` and takes a `Clock` (`protocol Clock { func now() -> Date }`, default `SystemClock`) so mutation timestamps are deterministic in tests — same purpose as the Avalonia client's `IClock`, needed because `Date.now`/`DateTimeOffset.UtcNow`-style calls aren't testable directly.
- **App icon:** master art is `_appicon/appIcon_1024.png` (1024×1024, no alpha, full-bleed square) — never hand-edit the derived files. `AppIcon.appiconset`'s iOS 1024 slot is the master itself; its ten macOS slots (`mac_*.png`) are generated by `_appicon/make-native-appiconset.sh` (run from the repo root; it also refreshes the iOS copy). Xcode's new-project template leaves the macOS slots without image files, and the build then succeeds silently with no icon at all (`Assets.car` holds only `AccentColor`, no `CFBundleIconName`/`CFBundleIconFile`) — check the built bundle, not the build log. macOS 26 masks and insets the full-bleed square into a squircle itself, so no pre-rounded variant is needed. The iOS dark/tinted 1024 slots are intentionally empty (single "Any" icon).
- **A loaded `@Model` instance does not refresh when another `ModelContext` saves** — only when something fetches it (verified on in-memory and file-backed stores, `container.mainContext` included, even after waiting). A live `@Query` does fetch: a hosted `@Query` view re-rendered after a `ModelActor` renamed and inserted rows (macOS; iOS still to be confirmed by hand). So the sync engine's saves reach the UI through `@Query`, but any test that asserts on an already-loaded item after the engine ran must re-fetch first (`Harness.reload()` in `SyncEngineTests`).
- `SyncEngine` conforms to `ModelActor` by hand (own `ModelContext`, `DefaultSerialModelExecutor`) instead of the `@ModelActor` macro so it can hold a client and cursor store; it compiles cleanly under Swift 6 mode.
- `UserDefaults` is not `Sendable` in this SDK, so `SyncCursorStore` is `@unchecked Sendable` (it is documented thread-safe).
- The Worker wire rules that bite (details in the vault's `phase-N2-worker-dtos.md`): nullable fields must be sent as explicit `null`, ids must be lowercase, and dates must use `Iso8601` (7 fractional digits, `+00:00`) because the Worker compares `updated_at` as text. Sync compare-and-clears `dirty` (an edit made during a push stays dirty) and applies an incoming row when its `updatedAt` is `>=` the local one, so a stale-rejected row whose write already reached the server resolves.
- The Xcode project's deployment target is iOS 26.5; simulators on older 26.x runtimes refuse to install the app.
- **macOS sandbox blocks all networking unless "Outgoing Connections (Client)" is on.** The target has App Sandbox enabled, and without the `com.apple.security.network.client` entitlement every request fails with `NSURLErrorDomain -1003` ("A server with the specified hostname could not be found", `Resolved 0 endpoints in 0ms`) even though DNS is fine — it looks like a DNS problem but isn't. Fix (Michael, in Xcode): target `TodoNative` > Signing & Capabilities > App Sandbox > Network > tick **Outgoing Connections (Client)** (build setting `ENABLE_OUTGOING_NETWORK_CONNECTIONS = YES`, verified on a scratch copy to add the entitlement). iOS has no such sandbox switch and was never affected. Verify on a built bundle: `codesign -d --entitlements - <TodoNative.app>` must list `com.apple.security.network.client`.
- **Signing / install:** automatic signing with team `T54JASTD4Z`, installs via Xcode (no scripts; the repo-root `scripts/` are Avalonia-era). A provisioning profile never outlives the certificate it embeds, so an install stops launching on the **certificate's** expiry date, not a year after install (Apple Development cert currently expires 2027-02-20). To list real certificate dates use the Python snippet in the vault's `phase-N4-signing-install.md` — a bare `openssl x509 -enddate` on `security find-certificate -a -p` output reads only the first cert and shows an old expired one. Verified without a device or account: Release builds compile for iOS (`generic/platform=iOS`, `CODE_SIGNING_ALLOWED=NO`) and macOS (`CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=`), and the ad-hoc signed Release Mac bundle carries `app-sandbox` + `network.client`.
- **Mac install route (confirmed working):** Product > Archive with My Mac as the destination > Organizer > Distribute App > **Debugging** (the Apple Development-signed export; Xcode 26.6 has no "Copy App" entry) > export > copy `TodoNative.app` to `/Applications`. The installed app carries `app-sandbox`, `files.user-selected.read-only` and `network.client`, is signed by the Apple Development cert with the hardened runtime, and has no embedded provisioning profile and no secure timestamp — so whether it keeps launching after the cert expires is unverified.
- **Manual ordering (N8):** `TodoItem.sortOrder` is a fractional key; `TodoItem.manualOrder` (`sortOrder` asc, then `createdAt` desc, then id) is the one ordering rule, used by the store and the Active/All lists. Any batch that changes rows (move, `renormalize`, backfill) must also set `updatedAt`, not just `dirty`: the Worker's `updated_at >` guard rejects an unchanged timestamp as stale, and `SyncEngine.clearDirty` compares on it. The Worker keeps its stored `sort_order` when a push omits `sortOrder`, and the client likewise never resets a local order from a pulled row that has none (`TodoWireDto.apply(to:)`). The one-time backfill runs from `SyncCoordinator`'s `afterSync` hook (after a completed sync, never in `TodoContainer.make`) and fires only when every live item is still 0. New items are appended to the **end** of the list (`TodoStore.create` uses `max(sortOrder) + 1`); `moveToTop` puts one above everything.
- **`.onMove(perform: cond ? handler : nil)` breaks the SwiftUI modifier chain** with a misleading `ambiguous use of 'toolbar(content:)'` on the next `.toolbar`, on both platforms. Use a computed optional closure property (`moveAction: ((IndexSet, Int) -> Void)?`) instead of a ternary.
- **In Swift, `NSNumber(0) is Bool` and `NSNumber(1) is Bool` are true.** A test that checks `JSONSerialization` output for "is a number, not a boolean" must compare `CFGetTypeID(number)` with `CFBooleanGetTypeID()`; `is Bool` wrongly rejects a `sortOrder` of 0 or 1 (`workerAcceptsPushItem` in `WireModelsTests.swift`).
- **Testing a SwiftData schema migration:** define a nested `@Model final class TodoItem` in the test as the old shape (SwiftData keys entities by type name, so it describes the same entity), write a file-backed store with it, release that container, then open the same URL with the real schema. Confirmed working for the `sortOrder` addition; see `SortOrderMigrationTests`.
- **The store lives in the App Group container; `TodoContainer.makeShared()` opens it.** The app calls it with the default `migrateLegacyStore: true`: it first *moves* an existing on-device store (`default.store` plus `-wal` and `-shm`, via `StoreMigrator`) into the group container, then opens it (a fresh install just creates it). It throws `appGroupUnavailable` rather than falling back to a private store, so the app crashes at launch if the App Groups capability is missing from the target. **Extensions call `makeShared(migrateLegacyStore: false)` and must never create the store**: they get `storeNotReady` until the app has run once, because an extension launching first would otherwise create an empty store and hide the real data. Previews and tests use `make(inMemory:)` or `make(storeURL:)`. `SyncCursorStore` stays in `UserDefaults.standard`: only the main app syncs.
- **`URL.path()` returns a percent-encoded string** (`Application Support` becomes `Application%20Support`), so any file-system call built from it fails on a path with a space. Use `path(percentEncoded: false)`. Caught by the `StoreMigrator` tests; the real legacy path has a space.
- **Extensions are separate processes with no Keychain or Worker access.** The Share extension (`TodoNativeShare`, iOS only) writes a `dirty` row through `TodoCapture` and stops; the item reaches the other device only after the main app next becomes active and syncs. The embed of the extension in the app carries `platformFilter = ios`, so the macOS build does not try to embed it. `NSItemProvider.loadObject(ofClass:)` has no async form; wrap it in a continuation.
- **Build and version numbers live at the project level** (`CURRENT_PROJECT_VERSION`, `MARKETING_VERSION`), with no per-target overrides, because an extension's `CFBundleVersion` must equal its parent app's. A new extension target's template writes its own `1` / `1.0`: delete those two rows on the new target so it inherits. The app target covers macOS and iOS, so those always match.
- **Mac quick capture** (`QuickCapture.swift`, `GlobalHotkey.swift`, `CaptureField.swift`, all `#if os(macOS)`): the `⌃⌥Space` hotkey uses Carbon `RegisterEventHotKey`, which works inside the App Sandbox with no Accessibility permission (verified). A `MenuBarExtra` popover cannot be opened programmatically, so the hotkey shows a borderless non-activating `NSPanel` hosting the same `CaptureField`; the popover is closed after a save with `NSApp.keyWindow?.orderOut(nil)` (verified it reopens). It runs in the main process, so it reuses the app's coordinator and syncs about two seconds later.
- **Notes are plain text; links are found at display time.** `Linkify.attributed(_:)` (`NSDataDetector`, `.link`) turns web addresses into tappable links in `TodoDetailView`. The edit sheet's `TextEditor` still shows raw text.
- **Widgets (`TodoNativeWidgets/`, Xcode target `TodoNativeWidgetsExtension`, iOS + macOS, bundle id `com.aurlaw.TodoNative.TodoNativeWidgets`):** `ActiveListWidget` (medium/large), `TodayCountWidget` (small, plus iOS-only Lock Screen accessories), `NewTodoControl` (iOS only), `CompleteTodoIntent`. They read the App Group store through `TodoContainer.makeShared(migrateLegacyStore: false)` and never sync (no Keychain or Worker access), so a widget shows local data: instant after an edit on this device, and after the app's next sync for changes from the other device. Widget entries carry `TodoSnapshot` value copies, never `@Model` objects.
- **The Active, Today and Upcoming membership rules live in Core as `TodoFilter`** (with `TodoQueries` for the widget reads); `Category.includes` in `ContentView.swift` delegates to it. Change a rule there, not in a view, or the widgets drift from the app. Every rule assumes a live item; callers exclude soft-deleted rows.
- **Widget reloads:** `WidgetReloader.reloadAll()` must run after any write, in whichever process made it. It is wired into `TodoStore`'s `onMutation` for the app, the Mac quick capture, the Share extension and `CompleteTodoIntent`, and into `SyncEngine`'s `onChangesApplied` and the sort-order backfill for changes that arrive by sync. A new write path that skips it leaves the widgets stale until the hourly refresh.
- **Deep links:** the `todonative://` scheme (registered in the app target's `Info.plist`) is parsed by `DeepLink` in Core (`today`, `new`, `item/<uuid>`) and handled by `.onOpenURL` in `ContentView`. On macOS the `WindowGroup` has `.handlesExternalEvents(matching: ["*"])` so a widget tap reuses the existing window instead of opening a second one (verified).
- **App Intents notes (checked against the iOS 26.5 SDK):** `openAppWhenRun` is deprecated in iOS 26 in favour of `supportedModes`. `AppIntent.isDiscoverable` (a static) hides an intent from Shortcuts. `NewTodoControl` opens the app with the system `OpenURLIntent(url)` inside a `ControlWidgetButton`, which works without a custom intent (verified). `CompleteTodoIntent.perform()` is `@MainActor` because `TodoStore` is.
- **The widgets project layout:** Xcode named the target `TodoNativeWidgetsExtension` while the source folder is `TodoNativeWidgets/` and the entitlements file sits at the project root. The project also carries a stray duplicate `TodoNativeWidgets` folder reference in the navigator that belongs to no target (harmless).
